## 2. Тактичний бій

### 2.1 Поле
- Квадратна сітка (не гекси) 🔶, великі істоти займають 2×2 (`CombatSize = 2`) ✅.
- Перешкоди генеруються випадково ✅: 0–6 малих, 1–2 великі, 1–4 змішані, загальна площа ≤ 21 клітинки,
  **2 крайні лінії біля армій завжди вільні** (`FreeLines = 2`).
- Стек = тип істоти × кількість. HP верхньої істоти зберігається між ударами.

### 2.2 Черговість ходів — шкала ATB (головна особливість HoMM5) ✅
- Замість раундів — шкала часу. Кожен юніт (і герой) рухається по ній зі швидкістю, пропорційною **ініціативі**.
  Хто дійшов до кінця шкали — ходить, потім повертається на початок.
- Герой має свою ініціативу (`HeroInitiative = 10`), тобто теж «юніт» на шкалі.
- Ініціатива середнього юніта ~8–11, швидкі (грифони) — 15. Тобто швидкий юніт ходить ~1,5× частіше.
- **Мораль:** добра мораль ставить юніта на 50% шкали одразу після ходу (`GoodMorale_ATBValue = 0.5`) — він
  походить ще раз раніше; погана — відкидає назад.
- Заклинання на кшталт «блискавки» з посиленням можуть зсувати юніта по шкалі (`EmpoweredLightningATBDrop = 0.3`).

> **Чому це варто взяти:** ATB дає тактичну глибину без додаткових правил — ініціатива стає окремим параметром
> поряд зі швидкістю (дальністю руху). Реалізується просто: у кожного юніта `atb ∈ [0,1)`, на кожному «тіку»
> `atb += initiative × k`, ходить той, хто першим дійшов до 1.

### 2.3 Формула шкоди
Константи з `DefaultStats.xdb` ✅: `DamageIncrease = 0.05`, `DamageIncreaseCap = 3`, `DamageDecrease = 0.05`, `DamageDecreaseCap = 0.1`.

Інтерпретація 🔶:
```
база   = random(MinDamage, MaxDamage) × кількість_у_стеку
якщо A > D:  множник = min(1 + 0.05 × (A − D), cap)        # кожна одиниця переваги атаки = +5%
якщо D > A:  множник = 1 / (1 + 0.05 × (D − A))  (з нижньою межею)  # кожна одиниця захисту ріже шкоду
шкода  = база × множник × удача × модифікатори_здібностей
```
- A = атака істоти + атака героя, D = захист цілі + захист її героя.
- **Удача:** вдалий удар ×2, невдалий ×0.5 ✅.
- **Оборона** (пропуск ходу) дає +30% захисту ✅ (`DefenceBonusOnDefend = 0.3`).
- **Контратака:** ціль відповідає один раз за свій хід (у здібностях є винятки «без відповіді», «безліч відповідей»).
- **Стрільці:** мають обмежені постріли (`Shots`), штраф за дистанцію і в ближньому бою 🔶; `PreciseShotRange = 3`.

### 2.4 Здібності істот (ідеї, які легко перенести як шаблон)
З `combat/Creatures` і `CombatAbilities.xdb` ✅ — у кожної здібності свої числові параметри в одному місці:
- **Розгін (Jousting):** +5% шкоди за кожну пройдену клітинку перед ударом.
- **Оглушення (Bash):** шанс збити юніта назад по шкалі ATB.
- **Атака з розгону через кілька клітинок** (`ChampionChargeMinimalDistance = 2`) — б'є всіх на шляху.
- **Пікірування зграї** (`PackDive_DamageMultiplier = 0.75`) — удар зверху з множником.
- Подвійний удар, удар по області, вампіризм, без відповіді, аура для союзників тощо.

> **Як у себе:** кожна здібність — окремий ресурс `.tres` з параметрами + код-обробник із хуками
> (`on_before_attack`, `on_after_move`, `on_turn_start`…). Юніт — список здібностей.

## 7. Генератор випадкових карт

### 7.1 Що є в даних
**Алгоритм зашитий у `.exe` — його немає.** Є **шаблони** (що генерувати) і **параметри** (обмеження).

**Шаблон = граф зон** ✅ (`RMG/Templates/S1-2P2-4Z4K1S.xdb` — малий, 2–4 гравці, 4 зони):
- **Зона:** розмір (відносна вага), тип (старт гравця / нейтральна / перехрестя / ресурсна), чи є місто і його охорона,
  шахти (кількість кожного типу), житла нейтралів, щільності: скарби, скрині, крамниці, святилища, будівлі удачі/моралі,
  ресурсні будівлі, **сумарна цінність скарбів** (`TreasureBlocksTotalValue = 50000`), в'язниці (герої).
- **Зв'язок між зонами:** звідки, куди, чи охороняється, **сила охорони** (`GuardStrenght`), широкий/вузький прохід.
- **Шаблон загалом:** мін/макс гравців, мін/макс розмір карти, чи є підземелля, чи є Грааль.

**Глобальні параметри** ✅ (`RMG/Params/Default.xdb`):
- шахти 1-го рівня на відстані 7–20 клітинок від міста, 2-го — 15–40, 3-го — 25–45;
- охорона шахт залежить від їхньої цінності (рівень 2 / 9 / 18 для звичайних / рідкісних / золотих);
- мінімальні відстані: між великими об'єктами — 15, між блоками скарбів — 5–8, між озерами — 10;
- стек охорони — 5–70 істот.

Назва шаблону кодує параметри: `S1-2` — розмір карти, `P2-4` — гравців, `Z4` — зон, далі тип/варіант.

### 7.2 Свій алгоритм (спроєктований з нуля за цією структурою)
1. **Шаблон → граф зон:** вузли (тип, розмір, ресурси, бюджет цінності) і ребра (сила охорони, ширина).
2. **Розкладка зон на карті:** force-directed (зв'язані зони притягуються, решта відштовхуються) або
   Вороного з центрів зон. Площа зони ∝ її розміру. Стартові зони — симетрично.
3. **Межі:** клітинки на кордонах зон заповнюються непрохідними перешкодами (гори, ліс, вода),
   крім **проходів** на ребрах графа (вузький — 1–2 клітинки, широкий — 3–5).
4. **Ключові об'єкти:** місто в центрі зони → шахти на кільцях відстаней → житла.
5. **Дороги:** A* між містом і проходами, дорога знижує ціну руху.
6. **Скарби:** витрачаємо бюджет цінності зони, ставлячи об'єкти з таблиці (ресурси, скрині, артефакти, святилища)
   з мінімальними відстанями між ними.
7. **Охорона:** на проходах — за `GuardStrenght` ребра; біля цінних об'єктів — сила ∝ цінності об'єкта
   (і зростає зі «складністю» карти).
8. **Перевірка:** flood fill — усе досяжне, кожен гравець має приблизно однакову цінність у своїй зоні; якщо ні — перегенерувати з іншим сідом.
9. **Детермінізм:** усе з одного сіду — тоді карту можна передати в мультиплеєрі просто числом.

Для ідей можна читати документацію генератора **VCMI** (відкритий рушій HoMM3) — **код не копіювати**, ліцензія GPL.

## 10. Як дістати ще щось

Скрипт-підхід (Python, без розпакування всього архіву):
```python
import zipfile
z = zipfile.ZipFile(r'D:\H5_Game\data\data.pak')       # потім a2p1-data.pak — він перекриває базу
names = [n for n in z.namelist() if n.startswith('GameMechanics/')]
```
Файли `.xdb` — звичайний XML. Тексти (назви, описи) лежать у `texts.pak` (посилання `NameFileRef`).
